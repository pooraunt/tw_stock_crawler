# 台股爬蟲 GUI（main_twstock_crawler.pyw）

`main_twstock_crawler.pyw` 是專案唯一的畫面入口，所有爬蟲的頁面都寫在這一個檔裡，爬蟲邏輯則在各自的模組。
`old_data/` 裡的舊 GUI 已退役，不要參考它們的寫法，也不要再載入。

## 與使用者合作的方式

- **外觀是主觀的，使用者要親眼比較。** 改配色或版面時存成另一個檔名（如 `main_twstock_crawler_v2.pyw`），
  舊版保留，兩個可以同時開來比。使用者選定後再併回 `main_twstock_crawler.pyw`，並刪掉比較用的檔案（刪之前先問）。
- **版面建議先列出來讓使用者挑**，每項編號、說明好處與代價，使用者會回「1、2、3 做，5 不要」。
  使用者看不懂某項建議時，用文字畫出前後對照的示意圖來說明。
- 先討論、說「開始」才動手，這點與爬蟲模組相同。
- 回報時明講驗證到什麼程度：是截圖看過、用假的爬取函式跑過流程，還是只確認能開啟。

## 外觀原則

- **莫蘭迪色系**：低彩度。淺綠、淡黃都試過，使用者不喜歡。

- **每個時間維度一個色相**：每日灰藍、每月灰綠、每季灰褐、每年灰玫瑰、不定期灰紫，
  定義在 `THEMES`。切到哪個選單，視窗底色、卡片邊線、標題、主要按鈕、進度條、捲軸都跟著換。

- **對比要夠，眼睛看了不吃力**：文字與底色的對比維持 4.5:1 以上。低彩度配色很容易讓說明文字太淡，所以改了任何顏色都要算過，不要用目測：
  
  ```bash
  python .claude/skills/tw-crawler-gui/scripts/contrast.py main_twstock_crawler.pyw
  ```
  
  檢查其他組合：`python .claude/skills/tw-crawler-gui/scripts/contrast.py "#566B7D" "#FFFFFF"`

- 卡片維持白底，主要文字固定用 `TEXT`，各頁的閱讀感才會一致；主題色只用在強調的地方。

- 淺色簡約：扁平按鈕、細邊框、留白用 `px()` 換算以配合螢幕縮放。

- 選單列要讓人一眼看出是選單：大字粗體、目前所在的選單深色底白字。
  只有一個頁面的選單按下直接切換，多個頁面的才下拉（名稱後加「▾」）。「結束」按鈕接在最後一個選單後面。

- Windows 內建的 `tk.Menu` 無法改字型與顏色，所以選單列是用按鈕自己畫的。

## 程式結構

- 頁面是 `make_page()` 回傳的 dict，不是 class。元件放 `page['w']`、tkinter 變數放 `page['v']`。
- 每個頁面由四個函式組成，以頁面代號為前綴（`annual_*`、`mix_*`）：

| 函式                        | 作用                                                              |
| ------------------------- | --------------------------------------------------------------- |
| `xxx_refresh()`           | 回傳資料庫卡片每一列的文字（list）；切換到該頁時會自動重讀                                 |
| `xxx_build(page, parent)` | 建立輸入區卡片                                                         |
| `xxx_prepare(page)`       | 按下開始時檢查輸入、呼叫模組的 `start_log`，回傳 `(總工作數, 背景函式, 參數)`；輸入有誤回傳 `None` |
| `xxx_worker(...)`         | 背景執行緒：逐期呼叫模組的爬取函式，回報進度與摘要                                       |

- 卡片用共用函式組：`build_db_card`、`build_period_card`、`build_scope_card`、`build_setting_card`；
  元件用 `make_card`、`make_inline_card`、`make_label`、`make_entry`、`make_button`、`make_radio`、`make_check`。
  需要新樣式時加一個共用函式，不要在頁面裡直接設定顏色與字型。
- 爬取中要停用的輸入元件用 `add_input()` 登記。
- 「請求間隔」維持獨立的設定卡片（使用者決定不併入期間卡片）。

### 新增一個頁面

1. 在檔案開頭 `import` 爬蟲模組。
2. 在對應的時間維度區段，照 `annual_*`（最精簡的完整範例）寫四個函式。
3. 在 `build_menus()` 對應的選單加一列 `make_page(...)`；`modules` 填入持有中止旗標的模組，
   留空表示不可中止（不顯示停止鈕與進度條）。
4. 屬於每日資料的新資料集不必加頁面，在 `DAILY_SETS` 加一列即可。

### 背景執行緒

- 爬取在背景執行緒進行，視窗才不會凍結。背景執行緒**不可直接操作 tkinter 元件**，
  一律透過 `msg_queue` 傳訊息（`('log', 文字)`、`('total', 總工作數)`、`('progress', 完成數)`、`('done', 狀態)`），由 `poll_queue` 更新畫面。
- 呼叫模組的爬取函式時包一層 `safe_crawl()`，未預期的例外記錄後視為失敗，不讓執行緒無聲結束。
- 每輪迴圈先檢查 `is_stopped()`；結束時 `log` 一行摘要（成功、無資料、失敗各幾個）再 `report_done()`。
- 同一時間只能跑一個爬蟲（`log_common` 是全域單一的），所以爬取中選單會鎖定。
- 會刪除資料的動作（如細產業的「全部重跑」）在開始前用 `messagebox` 確認。

## 驗證

改完至少做到：

1. **能開啟且每個頁面都能切換**，沒有例外。
2. **用假的爬取函式跑流程**：把模組的爬取函式暫時換成只 `log` 幾行、`wait` 一下就回傳狀態的替身，
   測開始、進度、完成、停止、選單鎖定與解鎖。不要為了測畫面去連線爬真實資料或寫入 `db/`。
3. **截圖看實際畫面**：配色與版面一定要看圖，不能只看程式碼。可在測試腳本裡於視窗顯示後用
   `PIL.ImageGrab.grab((x, y, x + w, y + h))` 擷取視窗範圍，存到暫存資料夾（scratchpad）再讀圖檢查；
   每個時間維度至少各看一頁。
4. 跑對比檢查。

下拉選單展開後的樣子、滑鼠移上去的效果這類截圖拍不到的部分，回報時請使用者自己點一次確認。
