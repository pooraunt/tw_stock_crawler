# 通用資料清理規則 (Data Cleaning Rules)

> 適用範圍：所有爬取自證交所 TWSE、櫃買中心 TPEx、公開資訊觀測站 MOPS、公告快易查的資料，清理後存入 `db/` 的 SQLite。
> 本檔只放**通則**。各資料集的欄位名稱，於實際撰寫該資料集的程式時再決定。
> 遇到規則未涵蓋的情況，在對應章節新增一條（編號接續），並登記於最後的「規則異動紀錄」。

---

## 1. 固定欄位 (Fixed Fields)

每種資料都有的兩個欄位，名稱固定：

| ID   | 規則                                           |
| ---- | -------------------------------------------- |
| R-01 | 股票代碼 (stock id)：欄位名稱 **`sid`**，型別 **string** |
| R-02 | 股票名稱 (stock name)：欄位名稱 **`sname`**，型別 string |

其餘欄位名稱不預先規定，**逐欄與使用者討論後決定**（R-18、R-19）。命名原則：

- **不強制英文**：可轉英文 snake_case，也可**保留原始中文，但精簡為能識別的中文名**（例：`營業收入-當月營收` → `當月營收`），依各欄位討論結果決定。
- 以**能識別意思**為主；同一資料表內不可重名。
- 來源若為**多層欄位名稱**（MultiIndex／表頭分層），一律改為**單層**（R-16）。

## 2. 通則 (General Rules)

| ID   | 規則                                                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------------------------------------- |
| R-03 | 數字中的**千分位逗號 (thousands separator) 一律移除**後再轉型                                                                                     |
| R-10 | 預設**全部欄位先以字串讀入**（如 `pandas.read_csv(dtype=str)`），清理後再轉型，避免代碼 `0050` 被轉成 `50`                                                     |
| R-11 | 字串先做 NFKC 正規化（全形轉半形，如 `－`→`-`）並去除前後空白（含全形空白 `　`、`\xa0`）。**名稱欄位不做 NFKC，只去空白**，避免改動字元                                              |
| R-12 | 缺值符號 `""`、`N/A`、`NA`，以及**全由 `-` 組成的字串（不限長度，如 `-`、`--`、`---`、`----`）**、**全由 `*` 組成的字串（不限長度，如 `*****`）**一律轉為 **NULL**，**不可用 0 取代** |
| R-13 | 缺值的列**保留**，不因單一欄位缺值而刪列                                                                                                           |
| R-14 | 無法解析的值**不可靜默略過**：丟出錯誤或記錄 log，由人工決定後再新增規則                                                                                         |
| R-15 | 以下欄位一律刪除：`漲跌價差`、`註記`、`出表日期`、`Unnamed: N` 這類空欄位。**其餘由 Claude 判斷不需要的欄位，須依 R-18 先討論，不得自行刪除**                                        |
| R-16 | 欄位名稱為多層時改為單層，各層相連（英文用 `_`）或改成能識別的精簡名稱                                                                                            |
| R-17 | **來源給什麼就存什麼**：不做來源以外的推算、補值或極端值替換                                                                                                 |
| R-20 | 逐檔或逐類別爬取的資料**只存上市、上櫃個股**，以 `company` 資料表的市場別判斷；興櫃與沒有代碼的不存                                                                        |
| R-21 | 同一期別有多份來源（上市＋上櫃，或多張報表）時，**全部成功才存檔**，避免存入只有一半的期別                                                                                  |

## 3. 各類資料規則

### 3.1 股票代碼 `sid`

- 型別 **string**，**不得轉成 int**（ETF 代碼可能有前導 0 與英文字母，如 `0050`、`00679B`）。
- 移除 Excel 式包裝 `="0050"`（CSV 下載常見）、前後空白，英文字母轉大寫。
- 入庫前：不得為 NULL；主鍵不得重複。

### 3.2 股票名稱 `sname`

- 一律存**簡稱**。同一來源若同時有全名與簡稱，簡稱存 `sname`，全名另用其他欄位。
- **不能只看來源欄位名稱判斷是全名還是簡稱，要看內容**（不同來源的「公司名稱」可能一個是全名、一個是簡稱）。
- 只去前後空白，不轉換「臺／台」等字。
- 名稱結尾的 `*` 是來源所附的標記（代表股票分割過），**保留不移除**（如 `聖暉*`）。
- 跨資料集比對一律用 `sid`，不用 `sname`（名稱會更名）。

### 3.3 數值

- 先移除 `,`，再去前後空白、`%`，最後轉型；正負號 `+`/`-` 保留。
- 無小數點 → INTEGER；有小數點 → REAL。股數、金額、筆數等計數類為 INTEGER。
- 百分比欄位存 REAL，**四捨五入到小數 4 位**。
- 金額單位**不換算**，維持來源單位，並於程式註解或欄位說明記錄單位。
- 價格類保留來源小數位，不再捨入。
- 來源為空字串的指標值 → NULL。
- 看似特殊值（如價格 `9999.95`）**照存**（R-17）。

### 3.4 文字

- 去前後空白即可。夾帶單位與大量空白的欄位（如 `新台幣      10.0000元`），丟出來討論後處理。
- 文字欄位的值若是 R-12 的缺值符號（如備註的 `-`）同樣存為 NULL；其餘文字照來源保留（如 `無`、`無。`）。

### 3.5 日期

- 日期一律轉為**西元**，pandas 的日期格式 **`YYYY-MM-DD`**（10 碼）。
- **只有年月的資料**（如月報）：日不重要但日期需完整，**日固定補 `10`**，即 `YYYY-MM-10`。
- 常見來源樣式與判斷：

| 來源樣式      | 實例          | 判斷                 | 結果           |
| --------- | ----------- | ------------------ | ------------ |
| 民國年 + 斜線  | `114/10/01` | 年份 < 1911 → 加 1911 | `2025-10-01` |
| 民國年 7 碼   | `1151008`   | 7 碼                | `2026-10-08` |
| 西元 8 碼    | `19501229`  | 8 碼                | `1950-12-29` |
| 民國年月 5 碼  | `11508`     | 5 碼，日補 10          | `2026-08-10` |
| 民國年月 + 斜線 | `115/7`     | 日補 10              | `2026-07-10` |

- **季資料**的 `date` 存該季財報的申報期限（Q1 `5/15`、Q2 `8/14`、Q3 `11/14`、Q4 次年 `3/31`），另存 `year`（西元）、`season` 兩欄。
- **非期別的資料**加 `crawl_date` 欄位，存該列寫入資料庫的日期。
- 轉換後驗證日期存在（如 2 月 30 日要報錯）。
- **不用 6 碼判斷民國或西元**（`991231` 與 `202510` 會混淆），遇到時報錯並新增規則。

### 3.6 列

- 表尾說明文字列要刪除：判斷依據為「數值欄位全為空，且 `sid` 不符合代碼格式」。代碼格式暫定 `^[0-9A-Z]{4,8}$`，可調整。
- 代碼不符格式且其餘欄位全空的列直接捨棄，不輸出訊息；代碼不符格式但其餘欄位有內容的列要報錯（R-14）。
- 重複列：以主鍵檢查，有重複則報錯，不自動去重。

## 4. SQLite 儲存規範

- 檔案放在專案 `db/` 資料夾；表名用 snake_case 英文。
- 型別對應：`sid`、`sname`、日期、代碼類 → TEXT；計數與金額 → INTEGER；價格與比率 → REAL。**日期欄位宣告為 `DATE`**，內容為 `YYYY-MM-DD` 文字。
- 主鍵依資料實際情況決定，譬如：(`sid`, 日期欄位)。
- 重爬不產生重複列。有期別的資料：同期別先刪除再新增；逐檔資料：內容有變才覆蓋。
- 資料表以 `CREATE TABLE` **明確宣告各欄型別與主鍵**後寫入，不讓 pandas 自動推斷（`sid` 必須為 TEXT）。

## 5. 入庫前檢查清單

檢查清單已寫成唯讀腳本，入庫前執行：

```
python .claude/skills/tw-crawler-dataset/scripts/check_db.py <資料庫路徑> <資料表>
```

- 月資料加 `--monthly`（檢查日為 `10`）；資料表沒有主鍵時加 `--key sid,date`；要核對筆數時加 `--expect 筆數`（原始筆數 − 刪除的說明列）。
- 檢查項目：欄位名稱、`sid` 型別與缺值、數值欄位殘留文字、日期格式、主鍵重複、整數欄位負值。
- 「錯誤」必須修正；「警告」（如金額為負）人工確認。
